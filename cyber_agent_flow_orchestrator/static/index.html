Trial settings

Uses rendered participant-guide hints, authored task hints, or discoverable facts. Tasks without usable guidance run unassisted and report that hints were unavailable. Edit task hints above when using custom tasks.

Optional, off by default. Intermediate hints are released after two turns without observed progress or an incorrect final answer. At the configured maximum tries, provide the current challenge’s facilitator walkthrough and exact answer/flag. A try is an agent turn without new observed progress; new progress resets the count. Other challenge answers remain withheld. Both conditions use the same policy, with up to three ordinary hints per trial and one solution per challenge. Results separate unassisted, hint-assisted and solution-assisted success.

Default: 6 agent turns without new progress. Applies only when progressive hints are enabled. The solution includes the walkthrough and answer for the first unsolved challenge. The trial still stops at its turn or time limit.

Experiment controls

Use extra hooks for persistent volumes or services outside ScenarioForge's deployment. A failed hook blocks the trial.

Reset redeploys the frozen scenario, including CORE targets. Changed objectives or answers block the trial. Agent budgets are identical across conditions; reset and judge time are reported separately.

Judge LLM

Required for tasks using Judge review or Both. The judge assesses each rubric requirement using execution evidence it read. The host calculates success, partial, fail or unverified. Exact-only tasks can run without it. Judge failures leave success unverified. Automated judgments have not been human calibrated.

A separate checkpoint review uses this judge model and saved tool output to check challenge milestones. Hints target the first eligible unfinished step. Missing evidence remains unverified; a monitor error releases no assistance. Checkpoint calls consume trial wall time and are reported separately from final scoring.

The endpoint must be reachable from the orchestrator host. Host credentials configured for that endpoint are reused; participant VM API keys are not copied. These judge settings are saved for reruns.
